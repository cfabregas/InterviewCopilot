# 面试辅助工具 · 功能实现技术方案

> 平台：macOS 14.4+，原生 Swift(SwiftUI + AppKit)
> 版本：v0.4(2026-11-15)，使用方式确定为仅自用
> 定位：个人自用工具，不对外分发，不做后端服务

## 1. 设计原则

**实时路径只做三件事：听清、译准、快上屏。其余一律会后做。**

| 放在实时路径(会中) | 放到会后 |
|---|---|
| 系统声道采集与录音 | 麦克风声道的回声消除与转写 |
| 面试官语音的流式转写 | 全程录音的高精度重转写 |
| 流式翻译与字幕上屏 | 多面试官说话人分离 |
| 问题检测与答案生成 | 全文重译、问答配对 |
| 麦克风原始录音(只录不处理) | 纪要、评分、改进建议 |

由此带来的简化：

- 会中不跑回声消除、不跑声纹聚类、不转写麦克风，CPU 和网络都留给听译。
- 会后拿到完整录音，离线模型可以看到全局上下文，分离和转写的准确度都比实时高。
- 会中字幕不带"面试官 A/B"标签，复盘页里才有。

## 2. 总体架构

```
┌────────────── 会中(实时路径) ──────────────┐
│ 系统声音 Tap ─► 16k 重采样 ─► VAD ─► 流式 ASR │
│      │                            │         │
│      │                    partial / final    │
│      │                            ▼         │
│      │        句段稳定器 ─► 流式翻译 ─► 悬浮窗字幕
│      │                            │         │
│      │              问题检测 ─► 答案生成 ─► 悬浮窗答案卡
│      ▼                                      │
│  录音文件(系统声道 + 麦克风声道，时间戳对齐)   │
│  实时转写与译文落库                            │
└─────────────────────────────────────────────┘
                     │ 会议结束
                     ▼
┌────────────── 会后(任务管线) ──────────────┐
│ 离线回声消除 ─► 高精度重转写 ─► 说话人分离    │
│ ─► 全文重译 ─► 问答配对 ─► 纪要与评分 ─► 复盘页│
└─────────────────────────────────────────────┘
```

### 模块划分(Swift Package)

| 模块 | 职责 |
|---|---|
| `AudioCapture` | 系统声音 Tap、麦克风采集、重采样、VAD、双声道录音 |
| `ASR` | `ASRProvider` 协议及各家实现(云端流式、本地) |
| `Translation` | 句段稳定器、翻译引擎、术语表 |
| `Copilot` | 简历解析、问题检测、答案生成 |
| `LLMClient` | 流式调用、重试、取消、provider 抽象 |
| `Storage` | GRDB 数据库、录音文件管理、Keychain |
| `PostProcess` | 会后任务管线(可断点续跑) |
| `App` | 悬浮窗、主窗口(历史、复盘、简历、设置)、菜单栏、全局快捷键 |

并发模型：音频回调线程只往无锁环形缓冲区写数据；其后每个环节是一个 actor，环节之间用 `AsyncStream` 连接。

### 运行位置划分

各环节分三类：本地运行、云端语音识别(不是大模型)、大模型接口。

| 环节 | 阶段 | 运行位置 |
|---|---|---|
| 音频采集、重采样、静音检测、录音 | 会中 | 本地 |
| 流式语音转写 | 会中 | 云端语音识别(断网时切本地模型) |
| 句段稳定器 | 会中 | 本地 |
| 实时翻译 | 会中 | 大模型(小而快的型号；断网时切系统本地翻译) |
| 问题检测 | 会中 | 本地规则预判，加大模型(小型号)分类 |
| 实时答案生成 | 会中 | 大模型(较强的型号) |
| 悬浮窗、共享检测、快捷键 | 会中 | 本地 |
| 简历文本提取 | 会前 | 本地 |
| 简历结构化、热词和术语表抽取 | 会前 | 大模型 |
| 回声消除、残余回声去重 | 会后 | 本地 |
| 高精度重转写 | 会后 | 本地离线模型(默认)，或云端批量接口 |
| 说话人分离 | 会后 | 本地 |
| 全文重译、问答配对、纪要与评估 | 会后 | 大模型 |
| 模拟面试出题、追问、点评 | 模拟 | 大模型 |
| 模拟面试朗读问题 | 模拟 | 本地(系统语音合成) |
| 数据库、录音文件、回放、导出 | 全程 | 本地 |

- 调用最频繁的是实时翻译：每个句段一次，60 分钟的面试有几百次调用，每次都很短。
- 对延迟最敏感的是流式转写和实时翻译，是双线路要重点保证的部分。
- 会后重转写默认放本地：没有延迟要求，省费用，录音不用再上传一次。
- 纯本地模式下，转写、翻译、录音、说话人分离可用；答案生成、纪要、模拟面试依赖大模型，不可用。

### 国内与海外双线路

产品要同时在国内和海外使用。海外接口在国内无法直连，国内接口在海外可用但延迟更高，而实时听译对延迟敏感，所以需要两套线路。

| 线路 | 语音识别 | 大模型 |
|---|---|---|
| 国内线路 | 国内供应商的流式识别 | 国内供应商的大模型 |
| 海外线路 | 海外供应商的流式识别 | 海外供应商的大模型(如 Claude) |
| 本地兜底 | WhisperKit 或 SpeechAnalyzer | 系统 Translation 框架(仅翻译) |

- **线路选择**：启动时和会议开始前对两条线路测速(建连时间加一次最小请求的往返时间)，自动选延迟低且可用的一条；设置里可以手动固定。
- **会中切换**：当前线路连续失败或延迟超过阈值时，先切本地兜底保证字幕不断，再在后台探测另一条线路，可用后切过去。切换以句段为边界，不打断正在上屏的句子。
- **按"地区 × 语言"选默认供应商**：国内识别通常中文和中英混说更强，海外识别英文更强。同一线路内也允许按面试语言配置不同供应商，默认值由 M0 的实测结果决定。
- **提示词分模型维护**：翻译、问题分类、答案生成的提示词按模型各存一份，两条线路分别验收质量。
- **配置形态**：每条线路是一份配置(供应商、接入地址、模型名、密钥引用)，支持自定义接入地址，便于接入代理或自建中转。
- **密钥**：仅自用，各供应商的 API Key 自己申请，存 Keychain，应用直连供应商接口，不经过任何中转服务。

## 3. 实时听译(最高优先级)

### 3.1 延迟预算

| 环节 | 目标(p50) | 上限(p95) |
|---|---|---|
| 音频分片发送 | 100 ms | 100 ms |
| ASR partial 上屏(原文) | 300 ms | 600 ms |
| 句末判定(endpoint) | 400 ms | 800 ms |
| 翻译首字 | 400 ms | 800 ms |
| **说完一句到译文完整上屏** | **1.2 s** | **2.0 s** |

### 3.2 音频采集

- **系统声音**：Core Audio Process Tap(`AudioHardwareCreateProcessTap` + 聚合设备)。只需要音频录制权限，不需要屏幕录制权限。可以只 Tap 会议软件进程，避开通知音和音乐。
- **备选**：ScreenCaptureKit 纯音频采集，作为 Tap 失败时的回退。
- **格式**：采集后统一重采样为 16 kHz 单声道 PCM16，供 ASR 使用；原始采样率的数据写入录音文件。
- **VAD**：本地 Silero VAD。无人说话时不向云端发音频，省费用，也给句末判定提供辅助信号。
- **断线保护**：保留最近 10 秒音频的环形缓冲，ASR 连接重连后补发，避免丢句。

### 3.3 流式 ASR

统一协议，供应商可替换：

```swift
protocol ASRProvider {
    func start(config: ASRConfig) async throws        // 语言、热词、采样率
    func send(_ pcm: Data) async
    var events: AsyncStream<ASREvent> { get }          // .partial / .final，含文本、起止时间、语言
    func stop() async
}
```

保证效果的四个手段：

1. **热词**：从简历和 JD 抽取公司名、产品名、技术名词，作为热词或提示词传给 ASR。这是提升技术面试转写准确率最有效的一项。
2. **语言策略**：会前选择"英文为主 / 中文为主 / 中英混合"。单语模式通常比自动检测更准，混合模式才启用多语言模型。
3. **选型靠实测**：做一个评测工具，把录音文件按真实速度灌入管线，输出各家的字错率、术语命中率、partial 延迟和 final 延迟。测试集用 10 段左右真实面试录音(英文技术面、中文面、中英混说各几段)。
4. **本地兜底**：网络异常时自动切到本地模型(WhisperKit，或系统自带的 SpeechAnalyzer)，恢复后切回。

候选供应商(具体能力和价格在接入时以官方文档为准)：

| 类型 | 候选 | 备注 |
|---|---|---|
| 海外云端 | Deepgram、OpenAI 实时转写 | 英文强；国内直连可能不稳定 |
| 国内云端 | 阿里云、火山引擎、讯飞的流式识别 | 中文和中英混说强，支持热词，国内延迟低 |
| 本地 | WhisperKit、Apple SpeechAnalyzer | 隐私好、零费用；流式延迟和混说效果需要实测 |

### 3.4 句段稳定器

ASR 的 partial 结果会不断被改写，直接翻译会导致字幕闪烁。稳定器负责决定"哪些文字可以送去翻译"：

- **原文行**：partial 结果立即显示，灰色；final 后变为正常颜色并不再改动。
- **译文触发**：
  - 收到 final 句段，立即翻译。
  - 长句未结束时，取"连续 3 次 partial 都没变的前缀"，在从句边界处切出一段先行翻译。
  - 单段超过 12 秒强制切分。
- **已上屏的译文不回改**。后续译文只追加，保证阅读不被打断。
- **过期请求取消**：新的 partial 推翻了旧前缀时，取消对应的在途翻译请求。

### 3.5 流式翻译

- **模型**：小而快的 LLM(如 `claude-haiku-5-5`)，流式输出。
- **提示词结构**：
  - system(固定，开启 prompt caching)：翻译规则、术语表、候选人背景一句话摘要。
  - user：最近 3 组"原文 / 译文"作为上下文，加当前待译句段。
- **规则**：只输出译文；技术名词、产品名、缩写保留原文；口语填充词(um、you know)省略；不确定的专有名词原样保留。
- **方向**：按句段语言自动决定，英文译中文，中文译英文；也可以固定方向。
- **顺序保证**：翻译请求并发发出，但按句段序号顺序上屏。
- **离线兜底**：网络不可用时用系统 Translation 框架做本地翻译。

### 3.6 验收指标(M1 / M2 出口)

- 英文技术面试录音：词错率 ≤ 8%，术语命中率 ≥ 90%。
- 中文面试录音：字错率 ≤ 6%。
- 延迟达到 3.1 的 p95 上限。
- 连续运行 90 分钟无崩溃、无丢句，内存不持续增长。
- 断网 10 秒后恢复，字幕不缺句。

## 4. 悬浮窗

### 4.1 窗口实现

```swift
let panel = NSPanel(contentRect: frame,
                    styleMask: [.nonactivatingPanel, .borderless, .resizable],
                    backing: .buffered, defer: false)
panel.level = .floating
panel.collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]
panel.isOpaque = false
panel.backgroundColor = .clear
panel.hidesOnDeactivate = false
panel.sharingType = .none          // 是否有效取决于系统版本和会议软件，见 4.3
```

### 4.2 布局与交互

- **字幕区**：最近 3–4 个句段，每段两行(原文小字、译文大字)，可切换"仅译文"。
- **答案卡**：有问题时展开，先显示要点，再流式显示展开内容；可折叠。
- **三种模式**：仅字幕、字幕加答案、极简单行。
- **外观**：不透明度 30%–100% 可调，字号可调，位置和大小可拖拽并记忆。
- **全局快捷键**：显示或隐藏、鼠标穿透开关、针对上一句手动生成答案、上下滚动、暂停转写。
- **不抢焦点**：点击悬浮窗不会让会议软件失去焦点。

### 4.3 共享屏幕时隐藏

这是全方案最大的不确定点，M0 必须先实测。

| 层次 | 做法 | 说明 |
|---|---|---|
| 第一层 | `sharingType = .none` | 有反馈称 macOS 15 之后基于 ScreenCaptureKit 的采集不再遵守该属性。要在目标系统上对 Zoom、腾讯会议、飞书、Teams 逐一验证。 |
| 第二层 | 检测到共享时自动隐藏 | 用 `CGWindowListCopyWindowInfo` 识别各会议软件"正在共享"的工具条窗口，按软件逐个适配，轮询间隔 500 ms。隐藏后答案可改为只在菜单栏图标上提示。 |
| 第三层 | 引导只共享单个窗口 | 共享窗口而非整个屏幕时悬浮窗不会入画。在设置页里给出说明。 |
| 远期 | 手机伴侣端或第二屏幕 | 内容显示在未被共享的设备上。 |

## 5. 简历与实时答案

### 5.1 简历处理

1. PDF 用 PDFKit 提取文本；Word 文档先转成文本。
2. LLM 结构化为 JSON：基本信息、工作经历、项目(背景、职责、技术栈、成果数字)、技能、亮点。
3. 可选粘贴 JD，抽取岗位要求和关键词。
4. 生成两份派生数据：ASR 热词表、翻译术语表。
5. 简历 JSON 和 JD 一起作为答案生成的固定 system 内容，开启 prompt caching。总量只有几千 token，不需要向量检索。

### 5.2 问题检测

- 输入：系统声道的 final 句段流。
- 合并：停顿不足 1.2 秒的相邻句段合并为同一轮发言。
- 判定：一轮发言结束后，用小模型分类为"问题 / 追问 / 闲聊或陈述"，输出 JSON，并给出规范化后的问题文本。
- 预启动：句段以问号结尾或带明显疑问句式时，不等分类结果，直接开始生成答案；分类结果为"非问题"再取消。
- 手动触发：快捷键随时可以对"上一轮发言"强制生成答案。自动检测漏判时靠它兜底。

### 5.3 答案生成

- **模型**：较强的模型(如 `claude-sonnet-5-5`)，流式输出。
- **上下文**：简历 JSON、JD、本场已出现的问答摘要(滚动压缩)、当前问题。
- **输出格式**：
  1. 要点：3–5 条，每条不超过 15 个词，1 秒内可扫完。
  2. 展开：可以照着说的口语化段落，100–150 词。
  3. 行为题按 STAR 组织，并且只引用简历里真实存在的项目和数字。
  4. 算法或系统设计题给出思路、关键取舍、复杂度。
- **语言**：默认跟随面试语言，可设置为"英文答案加中文要点"。
- **延迟目标**：问题结束到要点首字 ≤ 1.5 秒。
- **约束**：不得编造简历中没有的经历；信息不足时给出通用框架并标注"需结合自身情况"。

## 6. 会后处理管线

会议结束后自动启动，按顺序执行。每个任务幂等、可断点续跑，状态记录在数据库里；任务完成前，复盘页先显示会中的实时结果。

| 顺序 | 任务 | 做法 |
|---|---|---|
| 1 | 麦克风回声消除 | 离线跑 WebRTC AEC3，以系统声道为参考信号。离线处理可以用更长的滤波器，效果好于实时。 |
| 2 | 高精度重转写 | 两个声道分别用本地离线模型转写(默认)，也可配置为云端批量接口；带词级时间戳，替换实时转写结果。 |
| 3 | 残余回声去重 | 麦克风转写中与系统声道同时间窗、文本高度相似的句子删除。 |
| 4 | 说话人分离 | 对系统声道跑离线分离(sherpa-onnx)，得到"面试官 A/B/C"，按词级时间戳对齐到句段。用户可改名。 |
| 5 | 全文重译 | 用较强的模型带全文上下文重新翻译，术语前后一致。 |
| 6 | 问答配对 | 把面试官的问题和我的回答配成问答对，标注题型(行为、技术、系统设计、反问)。 |
| 7 | 纪要与评估 | 生成面试概要、问题清单、每题回答评价与改进建议、参考答案、待跟进事项。 |
| 8 | 导出 | Markdown 和 PDF。 |

预计耗时：60 分钟的面试在 5 分钟内处理完成(以 Apple Silicon 机器为准，M4 阶段实测校准)。

### 复盘页

- 左侧时间轴：按说话人着色的句段，点击跳转到录音对应位置播放。
- 右侧：问答对列表，每题显示问题、我的回答、当时给出的建议答案、评价、参考答案。
- 顶部：纪要全文、导出按钮。
- 支持按关键词搜索全部历史面试。

## 7. 模拟面试

- 根据简历和 JD 生成题单(行为题、技术题、项目深挖各若干)，可选岗位级别和面试语言。
- LLM 扮演面试官，TTS 朗读问题；用户语音作答，麦克风走同一套 ASR。
- 每题回答后给出点评，并根据回答内容追问 1–2 轮。
- 结束后复用第 6 节的纪要与评估任务，产出同样格式的复盘页。
- 顺带录入用户声纹，供真实面试的会后处理使用。

## 8. 数据模型(SQLite / GRDB)

| 表 | 主要字段 |
|---|---|
| `session` | id、类型(真实 / 模拟)、标题、开始与结束时间、语言模式、简历 id、录音路径、处理状态 |
| `segment` | id、session_id、声道(系统 / 麦克风)、speaker_id、起止毫秒、语言、实时原文、实时译文、终版原文、终版译文 |
| `speaker` | id、session_id、标签、用户改名、声纹向量 |
| `qa_item` | id、session_id、问题文本、题型、关联句段、会中建议答案、我的回答、评价、参考答案、评分 |
| `resume` | id、原文件路径、结构化 JSON、JD 文本、热词表、术语表 |
| `summary` | session_id、纪要 Markdown、生成时间 |
| `job` | id、session_id、任务类型、状态、进度、错误信息 |

录音以 AAC 存放在应用支持目录，系统声道和麦克风各一个文件，按主机时钟对齐。API Key 存 Keychain。

## 9. 权限、分发与合规

- **权限**：麦克风、系统音频录制；第二层共享检测需要读取窗口列表(可能触发屏幕录制授权，M0 确认)。
- **构建与安装**：仅自用，Xcode 本地构建后直接运行，不需要公证、安装包和自动更新。用固定的开发者签名构建，避免每次重新构建后系统权限授权失效。
- **隐私**：录音和转写只存本地；发往云端的只有 ASR 音频流和 LLM 文本；提供"纯本地模式"和一键删除。
- **合规**：录制通话在不少地区需要对方知情同意；很多公司禁止面试中使用 AI 实时辅助。产品内保留"仅听译和复盘"模式，实时答案可单独关闭。

## 11. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| `sharingType = .none` 在新系统上失效 | 共享时悬浮窗入画 | M0 实测；准备第二、三层方案 |
| 中英混说转写不准 | 听译核心体验下降 | 热词、语言模式选择、供应商实测择优 |
| 网络抖动或云服务不可达 | 字幕中断 | 环形缓冲补发、本地 ASR 和本地翻译兜底 |
| 海外 API 在国内不可达，国内 API 在海外延迟高 | 延迟高或不可用 | 国内与海外双线路，测速自动选路，本地兜底 |
| 两条线路的模型质量不一致 | 同一功能在两地体验不同 | 提示词分模型维护；两条线路分别按同一套指标验收 |
| 会议软件自身占用音频设备导致 Tap 异常 | 采集失败 | ScreenCaptureKit 回退；启动时自检并提示 |
| 长时间运行内存增长 | 面试中途卡顿 | 字幕只保留最近 N 段在内存，其余落库；M2 做 90 分钟压测 |
