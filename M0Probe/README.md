# M0Probe · M0 技术验证应用

验证两件事：悬浮窗在屏幕共享和截屏里是否可见；能否用 Core Audio Process Tap 采集系统声音。

## 构建与运行

```bash
./build.sh
```

```bash
open build/M0Probe.app
```

自动检测模式(跑完自动退出，结果写入日志)：

```bash
open -W -n build/M0Probe.app --args --autotest
```

日志和录音在 `~/Library/Application Support/M0Probe/`，日志文件是 `m0.log`。

没有开发者证书，应用用的是临时签名。每次重新构建后，系统可能要求重新授权。

## 当前结果(2026-11-15，macOS 27.2.1)

| 验证项 | 结果 |
|---|---|
| Process Tap 采集系统声音 | 通过。48 kHz 双声道，能采到其他进程播放的声音。 |
| ScreenCaptureKit 截屏里悬浮窗是否入画 | 通过。`sharingType = .none` 时整屏截图里看不到悬浮窗；对照组 `readOnly` 能看到。但悬浮窗仍出现在可共享窗口列表里，会议软件的"选择共享窗口"界面可能会列出它。 |
| Zoom、腾讯会议、飞书共享屏幕时悬浮窗是否入画 | 未测。需要手动操作。 |
| 共享状态检测(窗口列表对比) | 未测。需要手动操作。 |

## 需要手动完成的验证

### 1. 截屏检测

1. 系统设置 → 隐私与安全性 → 屏幕与系统音频录制，给 M0Probe 打开屏幕录制权限。
2. 重新打开 M0Probe，点"截屏检测悬浮窗是否入画"。
3. 日志里会出现"截屏检测结论"一行：`sharingType=.none 有效` 或 `无效`。

检测时悬浮窗要留在主屏幕上，品红色块不要被其他窗口盖住。

### 2. 会议软件实测

对 Zoom、腾讯会议、飞书各做一遍，建议用第二台设备或另一个账号入会观看：

1. 打开 M0Probe，确认悬浮窗显示 `sharingType = none`。
2. 在会议里共享**整个屏幕**，在观看端看悬浮窗是否出现。
3. 点"切换 sharingType"改成 `readOnly`，观看端应该能看到悬浮窗(对照组)。
4. 改为共享**单个窗口**，再看一次。
5. 记下每个软件在两种共享方式下的结果。

### 3. 共享状态检测

1. 入会但不共享时，点一次"导出会议软件窗口列表"。
2. 开始共享屏幕后，再点一次。
3. 输出目录里会有两个 `windows-时间.txt`，对比多出来的窗口(通常是共享工具条或边框)，就是检测共享状态的依据。
